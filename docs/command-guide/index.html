คู่มือรวมชุดคำสั่ง (Command Guide)

เลือกคำสั่งของ Nexus-DevFlow ทั้ง 15 Core Skills และส่วนเสริม Opt-in ตามลักษณะงานที่คุณต้องการทำ พร้อมคำอธิบายกลไกการทำงานอย่างละเอียด

Commands Matrix Reference CheatSheet Skills 15-Core-Skills

เลือกจุดเริ่มต้นตามประเภทงาน (Pick a starting point)

เริ่มต้นจากงานที่คุณต้องการทำ แล้วเลือกคำสั่ง Skill ที่ตรงจุด ทุกคำสั่งด้านล่างนี้สามารถรันได้โดยตรงใน AI Chat ของคุณ (ส่วนคำสั่ง Terminal เช่น npx nexus-devflow status ใช้สำหรับตรวจสอบสถานะและจัดการเครื่องมือ):

สิ่งที่คุณต้องการทำ คำสั่งที่แนะนำ หน้าที่และความรับผิดชอบ
มีไอเดียใหม่และอยากเทียบ 2–3 ทางเลือก /explore สำรวจโค้ดเบสจริงและเทียบ Option Trade-offs แบบ Read-only โดยไม่แก้ไขไฟล์
อยากรู้ขอบเขตของฟีเจอร์ถัดไปในแผนงาน /feature --preview พรีวิวขนาด ความเสี่ยง ผลกระทบ และแนวทางการแบ่งฟีเจอร์แบบ Read-only
พร้อมเริ่มพัฒนาฟีเจอร์ใหม่ตามแผนงาน /feature Adaptive Clarification (ถามเสริมเมื่อข้อมูลขาด) + สร้าง Living Spec
เกิดข้อผิดพลาด บั๊ก หรือระบบไม่ทำงาน /debug วินิจฉัยแบบ 2-Track (Track A เร็วเมื่อมี trace / Track B 6-phase isolation)
ต้องการแก้บั๊กเล็กหรืองานด่วนนอกแผน /fix สร้าง Spec สำหรับการแก้ไขบั๊กโดยเฉพาะ พร้อมวงจร TDD
ต้องการทดสอบระบบตาม Living Spec /check รันชุดตรวจสอบพฤติกรรมจริง (Multi-lane verification) ตามเกณฑ์ Done-when
ต้องการคู่มือขั้นตอนสำหรับทดสอบด้วยตนเอง /check guide สร้างคู่มือ Read-Only แนะนำจุดที่มนุษย์ควรคลิกทดสอบและผลลัพธ์ที่คาดหวัง
ต้องการตรวจสอบคุณภาพโค้ด + YAGNI /audit current สแกนคุณภาพ, YAGNI, ความปลอดภัย, ประสิทธิภาพ, Test และบันทึกลง findings.md
ต้องการตั้งค่า Unit Test / Playwright (Opt-in) npx nexus-devflow skill add setup-tests ติดตั้งส่วนเสริม /setup-tests สำหรับ Unit & Browser test harness
ต้องการทดสอบหรือแก้ปัญหา E2E ผ่าน BrowserOS neo (Opt-in) npx nexus-devflow skill add browseros-neo ติดตั้งส่วนเสริม /browseros-neo สำหรับ E2E Test Plan, Evidence และ Session Replay
ต้องการเช็กสถานะ, แนะนำคำสั่ง หรือตรวจสุขภาพ /devflow-help / /devflow-help doctor ศูนย์รวม Interactive Guide, Prompt Builder, สถานะงาน (--exec), ตรวจสุขภาพ และเราเตอร์คำสั่งเดิม

เส้นทางการพัฒนาประจำวัน (Everyday build path)

วงจรการพัฒนามาตรฐานที่ปลอดภัยและมีประสิทธิภาพที่สุดสำหรับการพัฒนาแต่ละฟีเจอร์:

/feature -> /implement -> /check -> /audit current -> /complete

ลำดับขั้นตอนและการทำงานของแต่ละด่าน (Quality Gates):

  • ตรวจสอบและอนุมัติ Spec ก่อนเริ่มเขียนโค้ด: ตรวจสอบ devflow/context/{xxx-slug}/spec.md เพื่อยืนยันขอบเขตงานและเกณฑ์การยอมรับ
  • /check พิสูจน์พฤติกรรมจริง: รันคำสั่งทดสอบจริงในสภาพแวดล้อมที่ใช้งานจริง เพื่อยืนยันว่าฟีเจอร์ทำงานถูกต้องตามเกณฑ์ใน Spec
  • /check guide แนะนำการทดสอบด้วยมนุษย์: อธิบายสิ่งที่คนควรคลิกทดสอบและผลลัพธ์ที่คาดหวัง (คู่มือนี้เป็นเพียงคำแนะนำ ไม่ใช่หลักฐานว่าการทดสอบอัตโนมัติผ่าน)
  • /audit current ตรวจสอบคุณภาพโค้ด: สแกนโค้ดที่เพิ่งแก้ไขเพื่อค้นหาข้อบกพร่อง ช่องโหว่ความปลอดภัย และบันทึกผลลงใน findings.md
  • /complete ส่งมอบงาน: สรุป Release Digest, ย้ายเข้า History Archive, ทำความสะอาด Workspace ชั่วคราว และทำการ Squash-Merge เข้าสู่ branch หลัก

สร้างและส่งมอบ (Build)

กลุ่มคำสั่งหลักสำหรับวงจรการพัฒนาและส่งมอบฟีเจอร์:

  • /feature: สกัดฟีเจอร์จาก devflow/build-plan.md กำหนดรหัสลำดับงาน (xxx-slug) และสร้าง Task-Isolated Living Spec (devflow/context/{xxx-slug}/spec.md), Stage Pointer (stage.md), และ Audit Ledger (findings.md)
  • /implement: สลับเข้าทำงานบน Branch feature/{xxx-slug} ดำเนินการพัฒนาตาม Checklist ใน Living Spec ด้วยระเบียบวินัย TDD (Red-Green-Refactor) และบันทึก Diff Evidence
  • /check: ทำหน้าที่เป็น Senior QA Gatekeeper ตรวจสอบ Multi-Lane Verification Matrix (Typecheck, Lint, Test Suites, Manual Proof) และบันทึกผลการตรวจสอบเชิงประจักษ์ลงใน Living Spec
  • /check guide: สร้างคู่มือการทดสอบแบบแมนนวล (Read-Only Try Guide) ระบุขั้นตอนการรัน จุดที่ต้องคลิกบนหน้าจอ และสิ่งที่ควรสังเกต เพื่อให้ผู้ใช้สามารถทดสอบด้วยตนเองได้อย่างง่ายดาย
  • /complete: ด่านตรวจความปลอดภัยขั้นตอนสุดท้าย บันทึก Release Digest, ย้าย Living Spec ไปเก็บถาวรใน devflow/history/features/, ทำความสะอาด Workspace ชั่วคราว, อัปเดต build-plan.md และ HISTORY.md, แล้วทำ Git Squash-Merge เข้าสู่ main

ทำความเข้าใจและตรวจสอบ (Understand and review)

กลุ่มคำสั่งสำหรับการวิเคราะห์ สำรวจ และตรวจสอบคุณภาพระบบ:

  • /explore: สำรวจโค้ดเบสจริงและเปรียบเทียบ 2–3 ทางเลือก (Brainstorm mode) แบบ Read-Only โดยไม่มีการแก้ไขไฟล์ใดๆ
  • /feature --preview: สรุปภาพรวมของฟีเจอร์ถัดไปใน Build Plan อธิบายขอบเขต ความเสี่ยง ผลกระทบ และแนวทางการแบ่งฟีเจอร์ย่อย โดยไม่สร้างไฟล์เกินจำเป็น
  • /devflow-help: Interactive Guide & Prompt Builder, รายงานสถานะภาพรวม (--exec), ตรวจสุขภาพด้วย /devflow-help doctor และเราเตอร์คำสั่งเดิม
  • /debug: วินิจฉัยแบบ 2-Track (Track A เร็วเมื่อมี deterministic stacktrace หรือ Track B 6-phase isolation) โดยไม่แก้โค้ดสุ่มสี่สุ่มห้า
  • /audit: ตรวจสอบคุณภาพ + YAGNI, OWASP Security, Performance, Architecture และ Test Integrity พร้อมโหมด independent

วางแผนและติดตั้งระบบ (Plan and setup)

กลุ่มคำสั่งสำหรับการเริ่มต้น ติดตั้ง และกำหนดโครงสร้างโปรเจกต์:

  • /onboard: รองรับทั้งโปรเจกต์ใหม่และโค้ดเบสเดิม (--adopt) ตรวจจับ Stack, คำสั่ง Test, Conventions และ Review Cadence โดยไม่กระทบ Git History เดิม
  • /discovery: สัมภาษณ์เชิงลึกและสำรวจ Roadmap ของผลิตภัณฑ์ เพื่อช่วยจัดทำและปรับปรุง project-plan.md และ build-plan.md
  • /overview: Deterministic Compiler คอมไพล์แผนงานทั้งสองฉบับเป็น devflow/context/project-overview.md (ขนาดกะทัดรัด < 20KB) เพื่อให้ AI โหลดเป็น Living Source of Truth ร่วมกัน
  • /prototype: สร้าง UI Mockup (HTML/CSS Standalone) และ Design Tokens อย่างรวดเร็วก่อนลงมือพัฒนาจริง
  • setup-tests (Opt-in Extension): ติดตั้งผ่าน npx nexus-devflow skill add setup-tests เพื่อจัดการและตั้งค่า Unit/Integration Tests รวมถึง Browser Testing (/setup-tests browser) ผ่าน Playwright และ Active Browser MCP
  • browseros-neo (Opt-in Extension): ติดตั้งผ่าน npx nexus-devflow skill add browseros-neo เพื่อวางแผนทดสอบ E2E (--verify) หรือดีบักปัญหา E2E (--debug) ผ่าน BrowserOS neo MCP พร้อมบันทึก browser-test-plan.md และ evidence.md ใน devflow/reports/{run-id}/ และผูก name_session ย้อนดูวิดีโอใน BrowserOS neo
  • ci (Opt-in Extension): ติดตั้งผ่าน npx nexus-devflow skill add ci เพื่อสร้างคำสั่ง Verify และไฟล์ GitHub Actions Workflow (devflow-verify.yml)

กู้คืนระบบและเตรียมปล่อยงาน (Recover and release)

กลุ่มคำสั่งสำหรับการแก้ไขงานด่วน กู้คืนประวัติ และเตรียมความพร้อมสำหรับ Production:

  • /fix: สร้าง Task-Isolated Spec สำหรับแก้ไขบั๊กเร่งด่วนหรืองานเล็กนอกแผน พร้อมวงจร TDD และบันทึกเข้าสู่ History Archive
  • rollback (Opt-in Extension): ติดตั้งผ่าน npx nexus-devflow skill add rollback แล้วรัน /rollback เพื่อวางแผนถอนฟีเจอร์ที่เสร็จสมบูรณ์แล้วอย่างปลอดภัย โดยอ้างอิงจาก History Archive และ Git Commit โดยรักษาประวัติ Git ไว้อย่างถูกต้อง
  • release (Opt-in Extension): ติดตั้งผ่าน npx nexus-devflow skill add release แล้วรัน /release เพื่อตรวจสอบความพร้อมสำหรับการ Deploy ขึ้น Production (Render / Vercel), เช็ค Build, Environment Variables, และ Health-Check Endpoint

ระบบอัตโนมัติ (Automation)

กลุ่มคำสั่งสำหรับการพัฒนาระบบแบบอัตโนมัติโดยลดการแทรกแซงของมนุษย์:

  • /devflow-mode: Lead-Coordinator + Playbook Router รันงานด้วย Isolated Subagents และ pstack (หรือรันคิวต่อเนื่องด้วย /devflow-mode --all)

รูปแบบการเรียกใช้และการย้ายคำสั่ง (Invocation and migration)

คุณสามารถเรียกใช้คำสั่งได้ตามรูปแบบที่เครื่องมือ AI ของคุณรองรับ:

  • Claude Code / Google Antigravity / Gemini CLI: ใช้เครื่องหมาย Slash เช่น /explore, /devflow-help doctor, /check guide
  • OpenAI Codex: ใช้เครื่องหมาย Dollar เช่น $explore, $devflow-help doctor, $check guide
  • GitHub Copilot / OpenCode / Chat ทั่วไป: พิมพ์ชื่อคำสั่งหรือระบุความต้องการเป็นภาษาไทยหรืออังกฤษได้โดยตรง

การย้ายและเปลี่ยนผ่านคำสั่ง (Command Migration)

ใน Nexus-DevFlow เวอร์ชันปัจจุบัน มีการยุบรวมคำสั่งให้เหลือ 15 Core Skills และย้ายส่วนเสริม Setup/Ops เป็น Opt-in Extensions:

คำสั่งเดิม (Legacy) คำสั่งใหม่ (Canonical) คำอธิบาย
/browser-tests, /setup-tests /setup-tests browser (Opt-in) รวมการทดสอบ Browser เข้าในส่วนเสริม setup-tests (ติดตั้งด้วย npx nexus-devflow skill add setup-tests)
/try /check guide รวมคู่มือการทดสอบด้วยตนเองเข้าเป็นโหมด Guide ของ /check โดยตรง
