โหมดพัฒนาอัตโนมัติรอบเดียวจบ (Single Bounded Loop) ควบรวม Spec + Code + QA พร้อมหยุดรอการตรวจทานก่อนส่งมอบ

01

What (คืออะไร & ทำอะไรได้บ้าง)

/autopilot คือโหมดพัฒนาอัตโนมัติแบบ 1 รอบการทำงานที่มีขอบเขตชัดเจน (Single Bounded Loop) โดย AI จะควบรวมการเขียนสเปก (/feature หรือ /fix), การเขียนโค้ด (/implement), และการตรวจเทสต์ (/check & Quality Gates) วิ่งต่อเนื่องจนจบ แล้วหยุดรอให้มนุษย์ตรวจรับงาน (Review Packet) ก่อนการ Commit และ Merge

  • Unified Pass — ควบรวม Preflight ➔ Living Spec ➔ TDD Implementation ➔ Multi-lane QA ในคำสั่งเดียว
  • Safety Boundary — หยุดก่อนการ Merge หรือ Push เสมอ เพื่อให้คุณตรวจผลงานก่อนส่งมอบ
  • Review Packet — สรุปความเปลี่ยนแปลง diff, ผลการรันเทส, และคำสั่งตรวจทานอย่างชัดเจน
02

Why (ทำไมต้องใช้ & ประโยชน์ที่ได้รับ)

  • ประหยัดเวลาและลดการขัดจังหวะ — ไม่ต้องคอยกด Approve ทุกขั้นตอนย่อย AI จะทำต่อเนื่องจนเสร็จพร้อมตรวจ
  • รักษามาตรฐานวิศวกรรมครบถ้วน — ยังคงรัน TDD, Typecheck, Unit Tests และเกณฑ์ความปลอดภัยเต็มรูปแบบ ไม่ตัดตอน
  • ปลอดภัย ไม่ทำลายระบบ — มี Safe Boundary หยุดก่อนการ Merge หรือ Push ขึ้น Git เสมอ
03

Who (เหมาะสำหรับใคร)

  • Solo Developers — ที่ต้องการให้ AI ช่วยเคลียร์งานใน Build Plan อย่างรวดเร็ว
  • Experienced Engineers — ที่มีข้อกำหนดในแผนงานชัดเจน และต้องการตรวจโค้ดทีเดียวตอนงานเสร็จเรียบร้อย
04

Where (ใช้กับส่วนไหน & สิ่งที่สร้าง)

⚠️
Human Final Gate: Autopilot จะไม่ทำการ squash-merge หรือ push ขึ้น remote ให้โดยอัตโนมัติ ต้องได้รับการยืนยันผ่าน /complete เสมอ
จุดทำงาน สถานะ หน้าที่
Feature Branch ACTIVE ทำงานแยกอิสระบน branch เช่น feature/xxx-slug
Task Workspace ACTIVE บันทึกสเปกและหลักฐาน QA ใน devflow/context/{xxx-slug}/
05

When (ควรใช้ตอนไหน & ลำดับขั้นตอน)

1
Preflight — ตรวจสอบสถานะและเช็กความพร้อมของ Git working tree
2
Spec Creation — ร่าง living spec และเกณฑ์ Done-When Criteria
3
TDD Implementation — เขียนโค้ดแบบ Red-Green-Refactor พร้อมรันเทส
4
Quality Gates — รัน multi-lane verification, lint และ audit
5
Review Packet Stop — แสดงสรุปงานให้มนุษย์ตรวจทานก่อนพิมพ์ /complete
06

How (ใช้งานอย่างไร & ตัวอย่างคำสั่งจริง)
