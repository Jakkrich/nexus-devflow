01

What (คืออะไร & ทำอะไรได้บ้าง)

book-to-skill คือเครื่องมือแปลงหนังสือและเอกสารทางเทคนิค (PDF, EPUB, DOCX, Markdown, HTML, RTF, MOBI) ให้กลายเป็น Structured Agent Skill โดยสกัดเฉพาะโครงสร้าง กรอบความคิด (Frameworks) กฎการตัดสินใจ (Decision Rules) และเทคนิคเฉพาะทาง แทนที่จะเป็นการสรุปย่อแบบทั่วไป

  • Deterministic Extractor — รันสคริปต์ไพทอน (extract.py) สกัดเนื้อหาและโครงสร้างอย่างแม่นยำ พร้อมโหมด technical (รักษา Code, Markdown Tables, Formulas ผ่าน Docling) และ text (สกัดความเร็วสูง)
  • On-Demand Chapter Indexing — แยกเนื้อหาเป็นรายบท (chapters/ch01-*.md) โหลดเฉพาะบทที่กำลังสนทนา ไม่กินโควตา Token ประจำรอบ
  • Standard Skill Layout — สร้างไฟล์ SKILL.md, glossary.md, patterns.md และ cheatsheet.md อัตโนมัติ
  • Multi-Agent Host Ready — รองรับ Google Antigravity, Claude Code, OpenAI Codex, และ GitHub Copilot ทันที
02

Why (ทำไมต้องใช้ & ปัญหาที่แก้ไข)

เมื่อนำเอกสารหรือหนังสือเล่มใหญ่โยนเข้าไปใน AI Context ตรงๆ AI มักเผชิญปัญหา Discovery Loop Tax:

  • เสีย Token ซ้ำซ้อน — AI ต้องวนอ่าน Table of Contents, ถอยกลับไปมา และอ่านเนื้อหาทั้งเล่มใหม่ทุกครั้งที่ถาม
  • อาการ Hallucination — เมื่อบริบทกว้างเกินไป AI มักตอบคลาดเคลื่อนหรือจำสับสนระหว่างบท
  • ประหยัดโทเค็น 24×–51× — จ่ายต้นทุนในการสกัดโครงสร้างเพียง ครั้งเดียว จากนั้นสืบค้นแบบเจาะจงเฉพาะบทที่เกี่ยวข้อง
  • Extract Structure, Not Summaries — รักษานิยามที่แม่นยำของกรอบการทำงาน เช่น ชื่อเฉพาะของแนวคิดและขั้นตอน Step-by-step
03

Who (ใครควรใช้งาน)

  • Software Architects & Tech Leads — ที่ต้องการแปลงหนังสือสถาปัตยกรรม (เช่น System Design, Clean Code, Microservices) หรือ ADR เป็น Skill ให้ทีม AI ร่วมอ่าน
  • Feature Developers — ที่ต้องการอ้างอิง RFC, Technical Standard หรือคู่มือ Library เล่มหนาระหว่างเขียนโค้ด
  • Domain Researchers & Analysts — ที่ต้องการรวมเอกสารวิจัยหรือคู่มือกระบวนการทำงานให้ AI ช่วยวิเคราะห์ในสเตจ /analyze หรือ /discovery
  • Solo Developers — ที่ต้องการฐานความรู้ส่วนตัวที่ค้นหาเร็วและไม่เปลืองโควตา Token
04

Where (ขอบเขตตำแหน่งไฟล์ & Artifact Locations)

องค์ประกอบ ตำแหน่งไฟล์ (Path) คำอธิบาย
Vendor Tooling devflow/.vendor/book-to-skill/ สคริปต์สกัดเนื้อหาและตัวตรวจเช็ค upstream (แยกเด็ดขาด ไม่ commit ลง git)

Playbook Doc devflow/docs/playbooks/book-to-skill.html คู่มือ 5W1H นี้ในรูปแบบ HTML Paper & Ink Light Theme
05

When (ควรใช้เมื่อใด & ลำดับการทำงาน)

  • Run Before (ก่อนหน้า):
    • เตรียมไฟล์หนังสือหรือเอกสารต้นทาง (PDF, EPUB, DOCX ฯลฯ)
    • รัน python devflow/.vendor/book-to-skill/scripts/extract.py --check เพื่อดูความพร้อมของตัวแปลงไฟล์ในเครื่อง
  • Timing & Triggers:
    • เมื่อเริ่มโปรเจกต์ใหม่และต้องการนำ Domain Knowledge หรือ Architecture Guide เล่มหนามาเป็นแนวทางพัฒนาร่วมกับ AI
    • เมื่อต้องการเพิ่มความสามารถเฉพาะด้านให้กับ AI Assistant ประจำโปรเจกต์
  • Run After (ถัดไป):
    • เรียกใช้งาน Skill ที่เพิ่งสร้าง เช่น /<my-book-slug> <หัวข้อที่ต้องการถาม>
    • นำสาระสำคัญไปต่อยอดในสเตจ /grill (ADR) หรือ /feature (Spec Generation)
06

How (ขั้นตอนการทำงาน & รูปแบบคำสั่ง)

1
เลือกและตรวจสอบเอกสารต้นทาง — รับพาธไฟล์หรือโฟลเดอร์ ตรวจสอบนามสกุลที่รองรับ
2
คัดแยก Content Type — เลือกระหว่าง technical (เน้นตาราง/โค้ด) หรือ text (เน้นความเร็ว)
3
สกัดเนื้อหาด้วย Python Extractor — รัน extract.py ได้ไฟล์ข้อความที่มีขอบเขตบทชัดเจน
4
สังเคราะห์ Skill Files — สร้าง SKILL.md, chapters/, glossary.md, patterns.md, cheatsheet.md
5
ตรวจสอบความถูกต้อง — รัน validate_skill.py ตรวจโครงสร้างและงบประมาณโทเค็น
powershell — nexus-devflow
PS >/book-to-skill docs/clean-architecture.pdf clean-arch --mode technical
→ Extracting clean-architecture.pdf using Docling extractor...
✓ Generated 12 chapters in .agents/skills/clean-arch/chapters/
✓ Synthesized SKILL.md, glossary.md, patterns.md, cheatsheet.md

คำสั่งพร้อมใช้งาน (Command Recipes):

/book-to-skill path/to/book.pdf [slug]
/book-to-skill analyze path/to/book.epub
/book-to-skill update path/to/extra.md existing-slug
python devflow/.vendor/book-to-skill/scripts/extract.py --check
🛡️
Vendor Safety Boundary: ไฟล์ใน devflow/.vendor/book-to-skill/ เป็น upstream read-only ห้ามแก้ไขโดยตรง หากต้องการอัปเดตเครื่องมือให้ใช้ npx nexus-devflow skill update book-to-skill
