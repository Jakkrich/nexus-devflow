01

What (คืออะไร & ทำอะไรได้บ้าง)

/bughunter คือเครื่องมือตรวจสอบช่องโหว่ความปลอดภัยเชิงรุกใน Nexus-DevFlow สแกนหาจุดอ่อน ข้อมูลความลับที่อาจรั่วไหล และตรวจสอบ API Endpoints ก่อนนำขึ้นสู่ Production

  • Attack Surface Mapping — ค้นหาจุดรับข้อมูลเข้า (Inputs), พารามิเตอร์ และจุดเสี่ยงที่มีการส่งข้อมูลจากภายนอก
  • Secret & Token Scanning — สแกนหา API Keys, JWT Tokens หรือ Credentials ที่อาจเผลอเซฟไว้ในโค้ด
  • Vulnerability Pattern Matching — เทียบเคียงกับคลังช่องโหว่จริงจาก HackerOne กว่า 681 รายการ
  • False-Positive Filtration — ตรวจสอบยืนยันเพื่อลดสัญญาณเตือนหลอก ก่อนบันทึกเข้า Finding Ledger
02

Why (ทำไมต้องใช้ & ประโยชน์ที่ได้รับ)

การตรวจจับช่องโหว่ด้วยตัวเองมักมีจุดบกพร่องที่มองข้ามได้ง่าย เช่น Broken Access Control, Injection, หรือ Token รั่วไหล:

  • ป้องกันข้อมูลรั่วไหล — ดักจับ Credentials หรือกุญแจสำคัญก่อนหลุดไปสู่ GitHub หรือระบบภายนอก
  • เสริมความแข็งแกร่งให้ QA — ผสานเข้ากับสเตจ /check และ /audit เพื่อปิดความเสี่ยงก่อน Deploy
  • ทำงานรวดเร็วและปลอดภัย — สแกนแบบ Read-Only ไม่แก้ไขโค้ดจนกระทบการทำงานเดิม
03

Who (เหมาะสำหรับใคร)

  • Security Auditors & QA Engineers — ผู้รับหน้าที่ตรวจรับรองความปลอดภัยของซอฟต์แวร์
  • Backend & API Developers — ผู้พัฒนา Endpoints, Auth Handlers, และ Data Access Layers
  • Solo Devs & Maintainers — ที่ต้องการความมั่นใจก่อนเปิดระบบเป็น Public หรือ Production
04

Where (ใช้กับส่วนไหน & ความปลอดภัย)

⚠️
Privacy & Safety: สแกนเนอร์ทำงานแบบ Read-Only ทั้งหมด และจะทำ Masking ข้อมูล Token หรือ Credentials ที่ตรวจพบเสมอเพื่อไม่ให้ความลับหลุดออกไป
ขอบเขตเป้าหมาย สถานะ รายละเอียดการตรวจ
API Routes & Controllers ACTIVE ตรวจจับ Auth Bypass, Injection, และ Data Validation
Configuration & Env Files ACTIVE สแกนหา Secret Hardcoded และ Missing Sanitization
Third-party Dependencies ACTIVE ตรวจจับ CVE ที่ทราบประวัติในแพ็กเกจที่ติดตั้ง
05

When (ควรใช้ตอนไหน & ลำดับขั้นตอน)

1
ก่อนใช้งาน (Prerequisites) — ควรผ่านการรันเทสต์พื้นฐานใน /implement ให้ทำงานถูกต้องก่อน จากนั้นจึงเริ่มสแกนด้วย /bughunter surface .
2
ระหว่างสเตจ /check หรือ /audit — ใช้ยืนยันความปลอดภัยใน Quality Gate ก่อนทำเครื่องหมายส่งมอบ
3
หลังตรวจพบ (Next Steps) — เมื่อพบบั๊ก ระบบจะบันทึกลง findings.md และส่งต่อไปยัง /fix เพื่อแก้ไขตรงจุด
