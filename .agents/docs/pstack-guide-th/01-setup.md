# บทที่ 1: ติดตั้งและตั้งค่า pstack

ในบทนี้คุณจะได้ติดตั้ง plugin เลือกโมเดลที่ pstack จะใช้งาน และลองรันงานแรกของคุณ การตั้งค่ามีเพียงคำสั่งเดียวบวกกับการตอบคำถามสั้นๆ

## ติดตั้ง plugin

ในหน้าแชทของ Cursor ให้รัน:

```text
/add-plugin pstack
```

Cursor จะยืนยันว่าติดตั้ง plugin เรียบร้อยแล้ว

ใน Claude Code ให้รัน `/plugin marketplace add cursor/plugins` แล้วตามด้วย `/plugin install pstack@cursor-plugins` โดย Claude Code จะเติม prefix หน้าคำสั่งของ plugin ทำให้ทุกคำสั่งในคู่มือนี้ต้องใส่ `pstack:` นำหน้า เช่น `/pstack:setup-pstack` ซึ่งจะเขียนไฟล์ตั้งค่าโมเดลไว้ที่ `~/.claude/rules/pstack-models.md` รายละเอียดความแตกต่างอื่นๆ ดูได้ใน [Claude Code adapter](../../harness/claude-code.md)

*(หมายเหตุสำหรับ Antigravity ในโปรเจกต์นี้: `pstack` ถูกติดตั้งไว้แบบ repo-local แล้วที่ `.agents/plugins/pstack/` พร้อมไฟล์ปรับแต่งคำสั่งที่ `.agents/plugins/pstack/rules/AGENTS.md` และไฟล์เลือกโมเดลที่ `.agents/rules/pstack-models.md`)*

## เลือกโมเดลของคุณ

รันคำสั่ง:

```text
/setup-pstack
```

[`/setup-pstack`](../../../skills/setup-pstack/SKILL.md) จะตรวจหาโมเดลที่คุณใช้งานได้ ถามระดับงบการคิด (reasoning budget) แสดงบทบาทแต่ละตำแหน่ง (ตัวเขียนโค้ด, ตัวตัดสินใจ, คณะกรรมการรีวิว) แล้วถามว่าคุณต้องการใช้โมเดลไหน แค่ตอบคำถามเหล่านั้น ระบบจะเขียนไฟล์ `~/.cursor/rules/pstack-models.mdc` (หรือ `.agents/rules/pstack-models.md` บน Antigravity) ซึ่งเป็น rule ขนาดเล็กที่ทุก skill ใน pstack จะอ่านก่อนทำงาน

ค่าเริ่มต้น (default) เทียบเท่ากับงบแบบ `large` งานเขียนโค้ด งานเขียนภาษาคน และงานตัดสินใจจะรันบน Opus 5.5 ที่ระดับการคิด `xhigh` ส่วนคณะกรรมการรีวิวและ swarm workers จะรันที่ `high` ไม่มีบทบาทไหนรันเกิน `xhigh` หากอยู่นอกคณะกรรมการรีวิว Fable 5.2 จะถูกเรียกใช้เฉพาะตอนที่คุณระบุชื่อเรียกเอง หรือหลังจากที่ Opus 5.5 รันโจทย์เดียวกันล้มเหลวครบ 2 รอบแล้วไม่ผ่านเกณฑ์ตรวจ งบแบบ `medium` จะลดระดับการคิดของทุกบทบาทลง 1 ขั้น และ `small` จะลดลง 2 ขั้น ซึ่งทั้งคู่ช่วยประหยัด token ลง

คุณกำหนด override เฉพาะบทบาทที่สนใจก็พอ บทบาทไหนที่ไม่มีบรรทัดระบุในไฟล์ rule จะใช้ค่าเริ่มต้นของ skill ต่อไป หากอยากกลับไปใช้ค่าเริ่มต้น ให้ลบบรรทัดของบทบาทนั้นทิ้ง เมื่อรัน `/setup-pstack` ซ้ำ ระบบจะเก็บค่าของบทบาทที่คุณตั้งไว้ต่างจากค่าเริ่มต้นเอาไว้ให้ แต่ถ้าค่าเริ่มต้นของ pstack เปลี่ยนแปลงไป ไฟล์ rule ที่เขียนไว้ก่อนหน้านั้นจะยังคงล็อกค่าเริ่มต้นเดิมอยู่จนกว่าคุณจะรัน `/setup-pstack` ใหม่อีกครั้ง รอบนั้นระบบจะแทนที่ค่าเริ่มต้นเดิมที่รู้จักให้ บอกให้ทราบว่าเปลี่ยนตรงไหน และคงตัวเลือกอื่นๆ ของคุณไว้ หากต้องการปลดค่าที่ระบบไม่รู้จัก ให้ลบบรรทัดนั้นหรือลบไฟล์ทิ้งก่อน

คุณอาจสงสัยว่าถ้าใช้โหมด Auto จะเกิดอะไรขึ้น หากตั้งค่าบทบาทเป็น `inherit-parent` หรือ `auto` ตัว pstack จะละฟิลด์ `model` ตอนสร้าง subagent ทำให้ subagent สืบทอดโมเดลจากแชทหลักของคุณมาใช้โดยตรง ทั้งสองค่านี้มีความหมายเหมือนกัน และไม่ใช่ชื่อ model slug สำหรับบทบาทที่เป็นคณะกรรมการรีวิว (panel) ค่าที่ใส่จะเป็นรายการโมเดล ระบบจะรัน subagent 1 ตัวต่อ 1 รายการ ดังนั้นความยาวของรายการจึงเป็นตัวกำหนดขนาดของคณะกรรมการ นอกจากนี้การตั้งค่ายังให้กำหนด `swarm workers` ซึ่งเป็นโมเดลเริ่มต้นของ worker ทุกตัวใน `/swarm` ยกเว้นกรณีที่การแข่ง (race) ระบุโมเดลแยกเฉพาะสำหรับแต่ละสายไว้แล้ว

## ตอบรับข้อเสนอสร้างระบบตรวจสอบ (หรือปฏิเสธ)

ในช่วงท้ายของการตั้งค่า `/setup-pstack` จะมองหาวิธีพิสูจน์พฤติกรรมของแอปในโปรเจกต์ของคุณ ไม่ว่าจะเป็น `verify-*` skill หรือ test harness ที่มีอยู่เดิม ถ้าไม่พบเลย ระบบจะเสนอสร้างให้ครั้งหนึ่งด้วย [`/create-verification-skill`](../../../skills/create-verification-skill/SKILL.md)

ถ้าตอบตกลง ระบบจะสร้าง `.cursor/skills/verify-<app>/` ซึ่งเป็น skill ประจำโปรเจกต์ที่สอนให้ agent กดใช้งานแอปของคุณแบบเดียวกับผู้ใช้จริง ระบบจะทดสอบรันให้เห็นว่า skill นี้ใช้งานได้จริง 1 รอบก่อนส่งมอบให้คุณ ถ้าตอบไม่ตกลง ขั้นตอนตั้งค่าก็จะข้ามไป โดยคุณสามารถเรียก `/create-verification-skill` เองเมื่อไหร่ก็ได้ รายละเอียดเชิงลึกอยู่ใน [บทที่ 6: พิสูจน์ผลลัพธ์และเปิด PR](./06-verify-and-ship.md#สร้าง-verification-skill-ประจำโปรเจกต์)

หากคุณเพิ่งเริ่มใช้ pstack แนะนำให้ตอบตกลงครับ Agent ที่ตรวจเช็กงานตัวเองได้จะทำวนไปจนกว่าผลตรวจจะผ่าน ส่วน agent ที่ทำไม่ได้จะโยนงานกลับมาให้คุณมานั่งกดตรวจเองด้วยมือทุกครั้ง ในบรรดาทุกอย่างในคู่มือนี้ verification skill ให้ผลตอบแทนคุ้มค่าที่สุด

จากนั้นระบบจะเสนอสร้าง formal verification skill อีกหนึ่งครั้งด้วย [`/create-formal-verification-skill`](../../../skills/create-formal-verification-skill/SKILL.md) เว้นแต่โปรเจกต์จะมีอยู่แล้ว ชุด test ทั่วไปตรวจได้เฉพาะเคสที่มีคนนึกออกแล้วเขียนดักไว้ แต่ formal verification skill จะตรวจคุณสมบัติสำคัญข้อเดียวของโค้ด เช่น "job จะไม่ถูกรันซ้ำพร้อมกันสองรอบ" กับทุกกรณีที่เป็นไปได้ภายในขอบเขตที่กำหนด ให้ตอบตกลงเมื่อโค้ดของคุณมีเรื่อง concurrency, ระบบ retry, state machine หรือ parser ที่บั๊กสร้างความเสียหายหนักและ test ทั่วไปเข้าไม่ถึงเคสพัง หากไม่ใช่ ให้ตอบปฏิเสธ แล้วค่อยมารันทีหลังเมื่อโค้ดเปลี่ยนไป รายละเอียดอยู่ใน [บทที่ 6: พิสูจน์คุณสมบัติด้วย formal verification skill](./06-verify-and-ship.md#พิสูจน์คุณสมบัติด้วย-formal-verification-skill)

หลังตั้งค่าเสร็จ ให้เปิดแชทใหม่ ไฟล์ตั้งค่าโมเดลจะมีผลกับ session ใหม่

## คุมค่าใช้จ่ายให้อยู่หมัด

pstack ใช้ token มากขึ้นกับ subagent และคณะกรรมการรีวิว นั่นคือราคาที่จ่ายเพื่อความรัดกุม ถ้าอยากลดการใช้ token:

- รัน `/setup-pstack` ใหม่แล้วเลือก reasoning budget ที่เล็กลง หรือใช้โมเดลที่ถูกลง การให้แชทหลักใช้โมเดลตัวเก่งแล้วใช้โมเดลที่เร็วและถูกลงในบทบาทเขียนโค้ดเป็นวิธีแบ่งที่ได้ผลดี
- ตั้งค่าบทบาทเป็น `auto` หรือ `inherit-parent` เพื่อให้รันบนโมเดลเดียวกับแชทหลัก
- ตัดรายการใน panel ให้สั้นลง เพราะ 1 รายชื่อเท่ากับ 1 subagent
- เก็บ `/poteto-mode` ไว้ใช้กับงานที่ต้องการความรัดกุม การแก้เล็กๆ น้อยๆ ที่เห็นชัดอยู่แล้วไม่จำเป็นต้องใช้

## รันงานแรกของคุณ

เลือกงานจริงขนาดเล็กมาสักอย่าง แล้วอธิบายแบบเดียวกับที่คุณคุยกับเพื่อนร่วมงาน:

```text
/poteto-mode add a --json flag to this command. text output stays byte-identical. verify both.
```

สังเกตดูที่ todo list รายการแรกๆ จะเป็นขั้นตอนของ playbook ที่ถูกคัดลอกเข้ามาแบบคำต่อคำ สำหรับ prompt นี้คือ Feature playbook

จากจุดนี้ คุณพิมพ์ตอบโต้ต่อตามปกติได้เลย หากต้องการเปิด `/poteto-mode` ค้างไว้ตลอดทั้งแชท ให้เลือกจากเมนู `/` แล้วกด Option+Enter (Mac) หรือ Alt+Enter (Windows) แทนการกด Enter ธรรมดา การทำแบบนั้นจะเปลี่ยนมันให้เป็น [Custom Mode](https://cursor.com/docs/skills#using-a-skill-as-a-custom-mode) ซึ่งจะค้างอยู่ใน context ทุกเทิร์นจนกว่าคุณจะออกจากโหมด Custom Mode ใช้งานได้ใน Agents Window และ CLI ของ Cursor ส่วนการกด Enter ธรรมดาจะแนบ skill ไปกับข้อความนั้นเพียงรอบเดียว แล้วผลของมันจะค่อยๆ จางหายไปเมื่อแชทเดินต่อ

บทถัดไป: [บทที่ 2: สั่งงานผ่าน `/poteto-mode`](./02-poteto-mode.md)

## สรุปท้ายบท

- **แก่นของบทนี้:** การตั้งค่า pstack คือการกำหนด "ทีมและงบสมอง" ให้ AI ก่อนทำงานจริง ด้วยคำสั่งเดียว (`/setup-pstack`)
- **3 สิ่งที่ควรจำ:**
  1. แบ่งโมเดลตามความยากของงาน (แชทหลักคุมทิศทาง, worker เขียนโค้ด, panel ตรวจทาน) และตั้ง `auto` / `inherit-parent` หรือลด panel ได้ทันทีถ้างบ token จำกัด
  2. **Verification skill** คือการลงทุนที่คุ้มที่สุดในระบบ เพราะทำให้ AI ตรวจงานตัวเองจนผ่านได้โดยไม่คอยมาติดคอขวดที่คุณ
  3. อย่าเอา `/poteto-mode` ไปใช้กับงานแก้คำผิดบรรทัดเดียว — เก็บไว้ใช้กับงานที่ต้องการความรัดกุมและพิสูจน์ผลได้จริง
