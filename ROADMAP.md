# Nexus-DevFlow Roadmap

Strategic direction and planned evolution for Nexus-DevFlow.

## Strategic Direction

Nexus-DevFlow is a local-first, stage-based workflow layer for building production software with AI coding assistants. It keeps product intent, active delivery state, verification evidence, and shipped history in durable Markdown/JSON contracts that can move between agents and IDEs.

## Phases

| Phase | Description | Target Status |
| :--- | :--- | :--- |
| **Phase 1: Foundation** | Overlay installer, multi-tool adapters, task-isolated living specs, quality gates, and consolidated Core Skills. | **Closing (115d)** |
| **Phase 2: Ecosystem Reliability** | Release migration contract, cross-platform installer matrix, bilingual routing evals, overview integrity, and upgrade resilience. | **Active Focus** |
| **Phase 3: Integration** | Status CLI/MCP sidecar pilot and cross-IDE continuation (Web Dashboard retired per Feature 128). | **Planned** |
| **Phase 4: Adoption** | Executable golden paths, documentation proof, and production release hardening. | **Later** |

## Current Focus

1. Complete independent re-review of the repaired Feature 115d P2 findings and close the Core Skills consolidation without adapter or documentation drift.
2. Establish a clear migration/release boundary for retired commands before publishing the consolidated workflow.
3. Prove fresh install and update behavior across supported operating systems and Node.js versions.
4. Expand Thai/English routing evaluation while preserving zero false activations in the declared benchmark.
5. Prevent placeholder or stale planning documents from becoming a misleading generated overview.

## Sequencing Guardrail

IDE sidecar work starts only after the consolidation release, cross-platform installer matrix, and planning integrity gate are green. This keeps Phase 3 on stable CLI/MCP contracts instead of embedding current migration debt into another interface.

## Explicitly Deferred

- Hosted SaaS, accounts, billing, and cloud sync
- Broad multi-editor support before one sidecar pilot is proven
- New Core Skills without measured routing or capability gaps
- Automated publishing, pushing, or deployment without explicit maintainer approval
